# 平板内容页：音乐库、歌手与专辑

这三页通过 `TabletPageContent` 接入独立的宽窗口展示，沿用原目的地、导航 entry、ViewModel 与业务操作。手机继续使用原有单栏内容，不新增一套路由或播放队列服务。

## 入口与文件归属

```text
ui/
├── component/artwork/PlaylistCoverStage.kt # 歌单与音乐库共用的封面构图
├── screen/
│   ├── main/library/
│   │   ├── LibraryScreen.kt          # 账号、加载、播放和导航操作
│   │   └── LibraryPageContent.kt     # 展示状态、操作与默认内容入口
│   ├── artist/
│   │   ├── ArtistScreen.kt           # 请求、取色、队列、菜单与导航
│   │   ├── ArtistDetailUiState.kt    # 展示状态与操作
│   │   ├── ArtistDetailContent.kt    # 原单栏展示
│   │   └── ArtistDetailComponents.kt # 可复用头部、简介与占位组件
│   └── album/
│       ├── AlbumDetailScreen.kt      # 请求、收藏、下载、菜单与导航
│       ├── AlbumDetailUiState.kt     # 展示状态与操作
│       └── AlbumDetailContent.kt     # 原单栏及共享歌曲行、操作组
└── tablet/
    ├── TabletPageContent.kt          # 注入三个宽布局展示函数
    ├── TabletContentMetrics.kt       # 可用宽度、字体与布局选择
    ├── component/TabletDetailPage.kt # 两栏骨架、图片与分区排列工具
    ├── library/TabletLibraryContent.kt
    ├── artist/TabletArtistContent.kt
    └── album/TabletAlbumContent.kt
```

`Screen` 函数仍是有业务依赖的装配入口。它读取 ViewModel／播放连接，绑定导航和操作，再调用传入的内容函数。`UiState` 与 `Actions` 是展示数据和回调，不拥有任务，也不保存服务对象。三个平板内容文件不读取 ViewModel，不直接调用导航控制器或播放器；菜单、下载确认等业务弹层仍归同一个入口处理。

共享组件按已有功能复用：音乐库左栏与歌单详情共用 `PlaylistCoverStage` 的错落封面构图及入场动画，普通封面用 `ArtworkCard`，歌手单曲用 `Track`，专辑复用 `AlbumActions`、`AlbumTrackRow` 和 `AlbumDescription`。两处封面直接复用同一组逐张骨架，位置、旋转、圆角和占位高度均由 `PlaylistCoverStage` 计算；像素加载期间仅未完成的单张图片保留 shimmer，完成后独立呈现，失败则显示普通占位。嵌套的 shimmer 容器复用上层效果，避免重复扫光。骨架在加载阶段固定于最终位置；每张真实封面解码完成时移除对应骨架和静止底板，再播放该封面的入场动画。图片背景随封面一起运动，不在原位保留第二层卡片。已完成入场的同一封面不因元数据刷新而重复掉落。新骨架容器只组织两栏，不生成第二套卡片、菜单或歌曲操作规则。

## 宽度与字体

应用外层仍从 600dp 起选择平板底栏；本批内容页在自己的 `BoxWithConstraints` 内测量可用宽度。普通字体下，两栏需要至少 840dp：336dp 资料栏、24dp 间隔及 480dp 内容栏。详情资料栏按总宽约 34% 分配，普通字体时限制为 336–420dp。音乐库侧栏按约 40% 分配、上限 480dp，封面构图填满扣除公共边距后的栏宽，避免额外的 280dp 上限；右侧仍至少保留 480dp，空间不足时优先满足两栏的最低宽度。

字体放大时同步增加资料栏和内容栏的最低宽度；窗口不足就复用现有单栏。判断不依赖方向、设备型号或物理屏幕分类。卡片列数也按内容栏宽度、字体和公共边距计算，不固定为横屏几列。实际安全区与底栏高度继续由应用外层提供，页内不重复消费 IME。

`TabletDetailPage` 统一顶栏与两栏的内容 inset。两个列表可分别滚动，Haze 来源覆盖其背后的完整内容。初始内容避开工具栏及玻璃淡出区域；顶栏从玻璃转为实色时不缩小内容 inset，避免跳动。图片沿用应用级 Coil 和缓存，每张独立加载。

## 各页内容

### 音乐库

左侧以“我喜欢的音乐”为视觉重点，复用歌单详情的三张错落封面及入场动画，取消整块卡片底座。按喜欢歌单顺序读取前三首歌曲封面，不使用带专属爱心的歌单封面；数量不足时沿用共享组件的单图或空态。下方标题与短胶囊“播放”按钮并排，间隔 12dp；数量与最近喜欢的歌曲位于下一行，信息组收紧并居中，随字体增大放宽。点击图片或文字进入该歌单。右侧直接展示自建歌单、收藏歌单，再展示收藏专辑，没有个人资料块或额外的顶部分类入口。

沿用业务层已有排序，不在展示层重新排序。自建概览排除已在左侧展示的喜欢歌单。自建最多预览 12 张、收藏歌单最多 8 张，超出时显示“全部”；收藏专辑只预览一行，超出同样进入原集合页。各数据分区独立显示加载、失败和空态，账号登录及同步重试仍调用原操作。喜欢歌单的封面元数据有独立加载状态，缺失项保留在原位置；文字与播放按钮只随歌单信息加载显示骨架，不等待封面全部完成。已知喜欢歌单会向详情页提供样式提示，使首次进入也使用错落封面骨架。

### 歌手

左侧是有界的歌手图片、姓名与译名／别名、身份、作品数量、热门播放和简介；保留专家身份标签，简介最多三行，“展开”在文字下方左侧，溢出时才显示。右侧预览 12 首热门歌曲和 12 张专辑，继续提供“全部”入口。

点歌仍由业务入口使用完整热门歌曲列表构建队列，不把页面预览数量当成队列上限。图片、歌曲、专辑分别显示请求状态并支持重试。

### 专辑

左侧是正方形封面、标题、歌手入口、年份、歌曲数量及播放／收藏／下载，简介最多预览六行。多歌手选择和简介继续使用原弹层。右侧展示歌曲及可选的页内搜索；搜索从顶栏更多菜单进入，输入框出现后滚到右栏顶部并获取焦点，关闭时释放焦点。

过滤后的行号仍对应完整专辑歌曲列表。点歌、收藏、下载和歌曲菜单均回到原业务入口；分享入口复用现有链接分享。

## 顶栏图片边界

歌手和专辑沿用 `rememberMeiArtworkTopBarState`，测量左栏实际图片底边和工具栏底边。左栏图片经过工具栏后显示实色背景，向回滚动恢复原策略；顶栏标题保持左对齐，只滚动右侧歌曲列表不会误认为左图已经离开。关闭玻璃且图片仍在顶部时透明，开启降低透明度时始终实色，服从公共策略。

内容顶部有 padding 时，图片可能仍显示在该区域内，而 `firstVisibleItemIndex` 已经为 1。因此不能仅用首项索引判断图片离开；只有第 0 项确实不在可见项中时才使用索引回退。其余时候依实际图片坐标判断。

## 状态与恢复边界

业务入口在布局选择之外，同一次组合中的宽窄切换不重新创建其 ViewModel、下载任务或播放操作。`AdaptiveTabletContent` 通过 `SaveableStateHolder` 分别保存单栏与双栏内容的可保存状态：两套布局各自记住滚动位置和已使用 `rememberSaveable` 的局部状态，返回该布局时恢复自己的位置。

**这不是跨布局的歌曲位置映射。** 首次进入另一套布局时从该布局默认位置开始；歌手和专辑尚未像歌单那样建立歌曲 ID 语义锚点。不能承诺窗口切换后仍停在同一首歌。Activity 重建仍只恢复各状态所有者已经保存的字段，不保证菜单、焦点、普通 `remember` 字段或所有弹层恢复。

## 验证

定向测试覆盖两栏阈值和大字体退回、每套布局的独立状态及 Activity 重建、音乐库播放与集合入口、专辑歌手合并、带内容 padding 的顶栏图片边界，并回归现有导航和音乐库逻辑。编译及状态／交互测试不能代替设备视觉验收；按协作约定不安装 APK，也不做截图或设备视觉检查。
