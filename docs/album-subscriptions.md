# 专辑收藏状态缓存

## 职责与入口

- `data/model/room/AlbumSubscription.kt`、`di/dao/AlbumSubscriptionDao.kt`：持久化服务器已确认的收藏状态，联合主键为用户 ID 和专辑 ID。缓存包含收藏与未收藏两种状态；没有记录表示未知。
- `data/repository/AlbumSubscriptionRepository.kt`：消费账号偏好，协调缓存观察、后台校准和收藏变更；沿用 `PlaylistRepository` 的现有接口，不在页面直接读写数据库。
- `ui/screen/album/AlbumDetailViewModel.kt`：在页面作用域观察仓库状态，处理操作中的按钮禁用和成功／失败反馈。手机、手机横屏和平板共用此入口。

## 读取与更新

进入专辑页时先显示当前账号的数据库记录，再后台获取专辑动态信息并更新缓存。缓存没有过期删除策略，每次开始观察都会校准；网络失败时保留已有记录。没有缓存且请求失败时保持未知，显示既有重试入口，不能把请求失败记成未收藏。

收藏或取消收藏只有在服务器返回成功后才写入数据库；等待期间保留此前已确认状态并禁用重复操作。接口失败或业务返回非 200 时，不改变缓存。数据库观察驱动当前页面和其他观察者更新。

同一用户、同一专辑的读取校准与写入串行执行，避免较早发出的状态请求覆盖刚完成的收藏操作。其他专辑互不阻塞。

## 账号与升级

账号须同时具有有效用户 ID 和登录 Cookie。退出登录时页面显示未收藏且禁止收藏，不发送状态请求；切换账号后观察对应用户的记录。请求前后核对登录会话，旧会话返回结果不写入缓存。Cookie 只用于内存中的会话核对，不写入表或日志。旧账号的缓存可保留，重新登录后仍先显示其独立记录并校准。

数据库从 19 升到 20，`MIGRATION_19_20` 仅增加 `album_subscription` 表；既有专辑、歌曲、红心及其他数据保持不变。应用注册的完整迁移链延续 8 → 20。迁移测试验证旧数据、全表结构、新表读写、按账号区分和重新打开后的持久性。
