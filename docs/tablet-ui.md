# 平板界面重构

本分支先完成独立布局入口与底栏，音乐库、歌手等页面随后逐页替换，不在手机页面中继续增加平板判断。

## 结构

- `MeiApp` 负责主题和共享依赖，只在这里选择 `PhoneApp` / `TabletApp`。选择依据是实际布局宽度扣除左右系统安全区后的可用宽度，600dp 起使用宽布局；不再以设备最短边或横竖屏给外层布局定型。窗口方向策略也在此集中处理：宽布局、全屏播放器展开或多窗口允许系统方向，其余紧凑布局维持原来的竖屏策略。
- `MeiAppState` 在手机 / 平板布局选择之外持有导航、搜索、当前主导航项和播放连接。同一次组合中的外层布局切换继续使用这些上层状态；Activity 重建后的恢复由各状态自己的导航保存、`rememberSaveable`、ViewModel 或重新连接机制负责，不保证所有页面局部状态保留。主导航选中项、搜索提交及页面切换后的查询重置也在这里统一处理；手机和平板只处理焦点及各自布局的滚动行为。
- `PhoneApp` 保留手机导航收起、mini player 位移与播放器几何；`TabletApp` 自己管理底栏、搜索、页面安全区与全屏播放器层。
- `MeiAppPages` 承载唯一的路由容器，`NavigationBuilder` 统一注册路由、解析参数和确定父页面作用域。导航内容的 `movableContentOf` 持有者放在外层选择之前：同一次组合中移动到另一种外层布局时，保留页面组合；Activity 重建后仍分别依靠导航与各页面的保存机制恢复。手机和平板通过 `MeiPageContent` 注入页面内容，避免复制整套路由图。
- 两种外层布局使用共享页面集合。歌单统一进入 `PlaylistScreen`，在自己的 `PlaylistContent` 中根据实际宽度选择单栏 / 双栏；不再通过手机和平板歌单转发入口选择排列。`TabletPageContent` 保留给后续确实不同的平板页面结构接入。
- `TabletPlayerHost` 保留播放状态和菜单处理，只在播放器展开时放置页面；折叠时不留下覆盖底栏的隐形点击区域。展开／折叠锚点由外层 `MeiAppState` 的 `rememberSaveable` 持有，手机和平板各自重建不同几何的 sheet 时共用该锚点；这不意味着播放器内全部临时面板也已保存。

## 底栏

顺序固定为：四个 tab → mini player → 搜索。四个目的地全部保留，不随列表滚动收起，也不再切换到横屏侧栏。

- 导航、播放、搜索分别放在 `TabletNavigationTabs`、`TabletMiniPlayer`、`TabletSearchField`，由 `TabletBottomBar` 组合。
- 按本轮确认的平板设计，导航、mini player、搜索按钮和输入框统一复用 `MeiGlassSurface`，跟随全局玻璃参数、增强清晰度及降低透明度；关闭玻璃时使用共享实色回退。此调整只作用于平板底栏。
- mini player 在普通字体下最大 340dp，大字体适度增宽，窄窗口按剩余空间收缩。导航、播放条与搜索以两个固定的 12dp 间距组成整体，在可用宽度内水平居中；多余空间均分在整体两侧，宽度不随歌名变化。
- 输入搜索时，中间槽位替换为输入框，最右侧变为关闭搜索；四个 tab 继续可用。
- 窄窗口或大字体下优先保留四个可操作图标与播放空间，导航标签按可用宽度显示；读屏名称与选中语义保留。
- 页面底部仅预留这条底栏的实际高度，不再叠加手机 mini player 高度。全屏播放器与底栏分别负责自己的命中区域。

公共内容边距通过 `LocalAppWindowLayout` 使用同一个外层选择结果（紧凑 20dp，宽布局 28dp），不再额外用设备分类独立推断。未接入应用外层的独立预览仍有旧设备信息回退。歌单双栏的 840dp 断点则由歌单内容层自行测量；宽底栏不要求所有页面都变成双栏。

## 页面替换约定

1. 在 `ui/tablet/` 增加确实需要不同布局的页面，在 `TabletPageContent` 覆盖对应方法。只需尺寸自适应的现有页面继续复用。
2. 路由字符串、参数类型和返回栈仍由 `NavigationBuilder` 管理。不要为同一业务对象复制第二套平板路由，也不要在路由注册处增加 `isTablet` 判断。
3. 页面的 ViewModel 默认属于原来的导航 entry。音乐库集合明确接收音乐库父 entry 的 `LibraryViewModel`，保持账号、列表和缓存一致。数据加载与播放服务沿用现有业务层。
4. 底栏、IME、安全区和全屏播放器的放置归外层布局管理，页面只消费统一的内容 inset。`TabletPlayerHost` 是当前播放器主体的兼容接入点，后续独立平板播放器从这里替换。
5. 新增设备判断前先区分外层布局选择、页面结构差异和普通尺寸自适应；前两者分别留在 `MeiApp` 和平板页面接入口，避免继续扩散到共享页面。

## 已拆分案例

歌单功能已集中为 `PlaylistScreen` 接入、纯展示 `PlaylistContent` 与单栏 / 双栏布局。排序草稿、搜索和下载待确认意图由 ViewModel / SavedStateHandle 管理，列表使用歌曲语义锚点恢复。目录、行为和验证边界见 [歌单页面架构与自适应布局](playlist-detail-architecture.md)。
