# LX 音源黑盒测试：2026-10-22

样本：用户提供的 `ChangQing.js` 和 `flowers.js`。仅由测试进程加载和执行；未查看、解混淆或输出样本源码。报告不包含播放 URL、原始接口响应、Cookie 或令牌。

运行环境为 QuickJS-KT 的桌面 JVM 原生库，配合 Robolectric 的 Android API 执行生产宿主、目录适配与 Media3 音频探测。没有安装 APK、进行视觉测试或在真机上播放。

## 结果

| 样本 | 初始化 | 实际取链与访问 |
| --- | --- | --- |
| ChangQing.js | 成功；声明支持 wy / tx / kw / kg / mg，以及 128k / 320k / flac | 返回 URL，但以下抽测的实际访问均为 HTTP 404，未确认可播放 |
| flowers.js | 失败，运行时 JS 错误 | 没有进入有效的取链验证；用户也反馈该样本可能失效 |

初始化失败本身不足以确认 flower 服务已经停运，也可能涉及脚本环境兼容；本次没有通过阅读源码进一步判断。

| --- | --- | --- | --- |
| 海阔天空 | 网易云 / QQ / 酷我 / 酷狗 / 咪咕 | 320k | 各平台都返回 URL；访问均为 HTTP 404、HTML 页面 |

追加排查：长青取链过程中观察到脚本 HTTP 接口返回 200，但后续音频地址返回 404；换成播放器的 User-Agent 后仍为 404。对一个网易云 128k 返回地址做同路径 HTTPS 对照，也返回 404（JSON 响应）。这些均没有被当成音频采用。

这些结论仅针对本次样本、歌曲、时间和当前网络，不能据此保证其他歌曲、其他版本音源或其他网络的结果。

## 发现并修复的问题

原探测器会把 HTTP 404 等传输失败当作某个提取器“不识别格式”，随后让其他提取器重复请求同一个地址。现在传输失败会立即结束本次 URL 探测，再交由 LX 继续尝试其他候选。新增本地 HTTP 回归用例验证失效 URL 只请求一次。

## 手动复测

黑盒用例默认跳过，不随常规测试自动读取任何外部脚本。明确指定目录并单独运行：

```sh
MEI_LX_SAMPLE_DIR=/path/to/lx_temp ./gradlew :app:testDebugUnitTest \
  --tests 'com.ljyh.mei.playback.source.lx.LxBlackBoxTest'
```

可加 `MEI_LX_SAMPLE_FILTER=ChangQing.js` 仅测试一个样本，也支持逗号分隔的多个文件名。新增三个样本的结果见 [追加样本报告](lx-blackbox-2026-10-22-new-samples.md)，付费样本结果见 [Lanyin 报告](lx-blackbox-2026-10-22-lanyin.md)。用例只输出脱敏状态、平台、音质、HTTP 状态及可识别的音频时长。JUnit 的通过只表示诊断流程正常执行，具体音源是否可用应查看 `LX_BLACKBOX` 报告中的状态，而非仅看构建成功。
