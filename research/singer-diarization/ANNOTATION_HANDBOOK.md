# 演唱角色数据集：完整试听与细标手册

本手册适用于当前数据集的全部候选。正式细标使用 **v2 完整试听任务台**；旧的五选一页面只适合初步行级归属，不能表达所有句中切换和背景人声，不再作为本轮细标入口。

目标是把一次听音形成的判断、依据、时间和疑点都留下，后续有问题能直接定位，而不是把整首歌从头再听。无法承诺永不返听：真实身份存疑、换录音版本、边界不清或评测抽查时仍需核对。应当减少的是因信息漏记、文件丢失、标注定义变化造成的整批返工。

## 一、先看任务状态，再决定做什么

| 状态 | 现在做什么 | 不该做什么 |
|---|---|---|
| 已粗筛标准候选 | 音频固定后，优先建立完整细标 | 不把“合格”批量转成逐句正确 |
| 已粗筛轮唱候选 | 定位可用轮唱，细标其余特殊部分 | 不只听中段就宣称全曲纯轮唱 |
| 困难样本 | 记录明确部分与疑点位置；保留未知 | 不依赖 TTML 猜出自己听不出的身份 |
| 独唱负例 | 用同一套细标规范，保持同人身份一致 | 不为了测试对唱强行分出第二人 |
| 片段用途 | 先标出实际可用片段；范围外不宣称有完整答案 | 不以少量片段代表整曲 |
| 尚待粗筛 | 判断实际歌手数、轮唱与合唱结构、可听辨程度 | 不直接当成双人训练样本 |
| 本地音频缺失／试听／版本可疑 | 保留粗筛，先取得并固定完整录音 | 不花大量时间细标另一份未知录音 |
| 历史排除 | 保留理由；日后若研究负例／困难样本可复议 | 不删除原始音频和标签，也不偷偷重新纳入 |

候选池里的 strict、balanced 是歌词结构筛选等级，不是人声难度等级，不是人工正确率。两个 TTML 角色可能是同一个人的不同声部，也可能代表一组人；两个格式一致也不等于两份独立答案。

## 二、启动与文件入口

在 Mei 根目录运行：

```bash
python3 research/singer-diarization/tools/prepare_listening.py
python3 -m http.server 4174 --bind 127.0.0.1 --directory research/singer-diarization
```

打开 <http://127.0.0.1:4174/data/listening/>。

任务台可以搜索全部歌名、元数据歌手和 ID，按用途筛选，查看每行风险，试听整行或具体片段，添加身份参照、分段和备注，导出草稿及待校验结果。默认同歌词只显示代表 ID；取消该选项可查看同歌词对应的其他 ID。

- 总清单：`data/listening/all_pending.tsv`。
- 完整目录及统计：`data/listening/catalog.json`、`summary.json`。
- 已有音频／已收到反馈的清单：`data/listening/KNOWN_SONGS.md`。
- 每首详细任务：`data/listening/tasks/<id>.json`。
- 对应歌词快照：`data/listening/lyrics/<id>.ttml`。
- 正式导入的细标：`data/detailed_annotations/<id>.json`。
- 已被替换的细标历史：`data/detailed_annotations/history/`。

原先 `data/labels/`、`data/verified/`、人工反馈日志均保留，不自动升级成 v2 答案。任务生成器不会覆盖正式细标。

## 三、按这个顺序安排听音

1. **第一首《发现爱》**：作为规范试运行，先做几行并导出、校验，确认文件能保存、恢复和读回。不要先标完几十首才第一次导入。
2. 其余四首已认可标准候选：《珊瑚海》《小酒窝》《铁血丹心》《世界真细小》。同一首可同时有轮唱、合唱、短句、和声，不再强制归入唯一结构类型。
3. 《Chinatown Blues》：你确认中后段适合轮唱，仍需记录合成声领域属性，以及全曲其余部分。
4. 《表白》：你已确认同一人，保留为独唱负例；以前的 B 候选不能再当第二人答案。
5. 《現夢 -genmu-》：相似音色困难样本。清楚的标，不清楚的记精确时间和原因；不自动丢掉原第三角色。
6. 《Havana》：只筛选实际有用片段，范围单独记录；不当作整曲标准轮唱。
7. 候选储备池：先做歌曲级粗筛，再取得固定录音，最后细标。它是储备，不要求一次听完上千首。

暂时不用一边标注一边决定训练／测试集。达到足够样本后，再按同曲、录音版本、真实歌手分组划分；不要把同一首的行随机分到不同集合。参与反复规范试验的《发现爱》优先作为开发样本，不作为未经查看的最终测试歌曲。

## 四、正式细标前必须固定录音

### 4.1 记录版本

需要记录：平台 ID、歌名、版本说明、录音来源、本地文件、音频 SHA-256、时长、歌词 SHA-256。任务台自动填写已有文件指纹；录音来源及“原版／Live／剪辑／重录”等由人核对。

- 同歌名、同歌手不代表同一份录音。
- 音频够长只排除了明显试听片段，不能证明版本正确。
- 高低码率、重新编码、剪去静音都会改变文件指纹。已有细标不跨指纹自动复用；以后若确定只是等价转码，可由专门映射保留原答案，不能现在假定。
- 如果同一个 ID 下出现多个音频文件，先选定其一；工具会把它列为阻塞，避免随便选第一份。
- 没有固定音频的任务可以导出草稿和粗筛笔记，但不接受为正式细标答案。

### 4.2 核对前、中、后三处同步

每处记录：**原歌词时间、实际音频时间、可复听定位词／声音、人工确认**。定位词要能唯一定位该处，不只写“正确”。自动给出的三处是起点，可换成更清晰的词。

例：原歌词 10.000s 的一个清晰发音实际出现在 10.300s，偏移为 +300ms。`offset_ms = 音频时间 - 原歌词时间`。偏移的单位是毫秒，而页面片段边界显示的是音频秒。

- 三处偏移接近：可以把全曲偏移作为定位辅助。
- 偏移越往后越大：考虑速度差、剪辑或时间轴漂移，不能只改一个 offset 掩盖。
- 某一段突然跳变：记录该段具体位置，检查版本或局部歌词时间。
- **最终片段 start/end 永远使用实际音频时间**，原 TTML 时间保持不变。不把全曲偏移重复加两次。
- 早期约 100ms 内定位可作为本项目的细听目标，不是你已经达到的精度，也不是通用评测标准。听不出精确边界时选择“近似定位”或“仍有疑问”，不编造精度。

## 五、先建立“谁是谁”的参照表

### 5.1 身份 ID

A/B/C 只表示本曲不同歌手，不表示男女、高低音、左声道或先后段落。建议按首次能确认的出现顺序编号，但全曲一致比顺序更重要。

- 同一人的低音、高音、假声、气声、说唱、效果器声，仍使用同一个 ID。
- 两个同性或相似音色歌手，只要有可靠依据，使用不同 ID。
- 实名不是必填；不知道名字不影响本曲匿名归属。
- 元数据里的别名、英文名、繁简体不能当作不同人。
- 一组未能区分具体成员的合唱声，不捏造一个确定的人，也不自动拆成任意两人；标记未知并备注“多人组声”。

### 5.2 每位保留清晰参照片段

为每位记录至少一段容易单独听清的独唱起止时间，最好再留一段不同音区／唱法的参照。2–5 秒可作为选段起点，具体以是否足以辨认这个声音为准，不要求机械截相同长度。

参照备注可以写“较低、带气息、此处念白与主歌同一人”等，但不能只凭“男／女”确定身份。没有可用独唱参照时明确填写原因，不硬找一段重叠声冒充独唱。

声音来源记录“真人／合成／不清楚”。《Chinatown Blues》这类合成声内容保留，不与纯真人数据混报。听不出来源时选择不清楚，不用标题代替声学确认。

## 六、逐句记录什么——这张表不要漏

| 项目 | 必须留下的内容 | 作用 |
|---|---|---|
| 原歌词行 | 行号、原文、原时间与源角色，工具保存 | 追溯；源角色不是答案 |
| 实际行窗口 | 此行对应音频中的实际开始／结束 | 修正源时间，不改坏原始文件 |
| 行内时间片段 | 每次身份集合／前背景角色变化的实际边界 | 支持句中换人、独唱转合唱 |
| 人声活动 | 演唱、说话／念白、无人声、无法判断 | 避免间奏和器乐误当歌手 |
| 主唱身份集合 | 可以一个、多个或带未知身份 | 对应前景演唱 |
| 背景身份集合 | 与主唱分开；未知背景明确勾选 | 后续可以分别评价主唱与全部人声 |
| 不同人重叠 | 实际同时出现的身份集合 | 不用纯“合唱”一词替代身份 |
| 同人叠唱 | 有、未听出、不清楚、不适用 | 不把多轨数量当歌手数量 |
| 演唱关系 | 独唱、齐唱、和声、adlib、不清楚 | 结构标签；与身份判断分别存 |
| 确定程度 | 身份确定／有疑问；时间精确／近似／有疑问 | 评测时区分答案质量 |
| 疑点 | 精确时间＋问题＋为什么无法确认 | 后续只回听该处 |
| 人工确认 | 听完该片段后单独勾选 | 点击播放或已有 TTML 不算完成 |
| 行完成状态 | 未开始、部分、所有片段已检查、保留疑点等 | 支持分次听，不假装全曲完成 |

如果一行有“已检查”的片段，也有没听完的部分，行状态是“部分记录”。“所有片段已检查”要求实际窗口被已核对片段覆盖，不能中间漏一段而宣称完成。窗口中有静音可明确加“无人声”片段，不能用猜测的人声填满。

**无需制作多个重复标注文件来记录短句、快切换和合唱。** 先把边界和身份集合记录清楚，后续按不同阈值自动统计。例如短于 1/2/3 秒、相邻换人间隔等都可重算，避免以后改定义就要求重听。源歌词“短于等于 2 秒”只是一种自动优先提示。

## 七、最容易标错的情况，逐项对照

### 7.1 一句先 A 后 B

例：实际音频 30.000–31.200s 为 A，31.200–33.000s 为 B。

记录两个连续片段，各自只选一个主唱。**不能整句选 A+B**，因为两人没有同时唱。切点不清则写大约时间并标边界不确定；不要编造一个毫秒级答案。

页面可在当前播放位置拆分片段。拆分后两段会取消“已核对”，防止复制的身份被误当人工确认；根据听音修正各段身份。

### 7.2 A 独唱后 B 加入

例：40–42s 为 A；42–44s 为 A 和 B 同时唱。记录两个片段：前一段主唱 A，后一段主唱 A、B。两人同旋律时标齐唱，明显不同声部则标和声，听不出就留不清楚。

### 7.3 同一个人叠唱／唱法变化

仍使用同一个身份。若听到自己录的多轨，记录“同人叠唱有”；仅听到音色变化不足以证明另一个人。无法判断是否同人时保留未知，不受源 TTML 两个角色引导。《表白》特别用于检查这个问题。

### 7.4 主唱 A，背景 B

主唱选 A，背景选 B。不要为了表面上“一句一个答案”丢掉 B，也不要把背景身份 B 强行写成主唱 B。

若明确有背景声但听不出是谁：主唱 A 不变，勾选未知背景并写原因。信息仍可用于“前景已知、背景未知”的分任务研究，而不是把整段当成没有和声。

若背景也是 A：前景 A、背景 A，结合听感标同人叠唱；全局活跃身份集合仍只有 A，不按两次计人数。

### 7.5 两人不同歌词同时唱

保留两条歌词行各自的片段，不把原歌词合并。各自记录其实际主唱和重叠时的背景人声。最终全局歌手活动由重叠片段取身份并集，不能把两条时间轴当作只能二选一，也不能重复计算同一身份。

若未能分辨哪位唱哪条词，记录该处未知并说明，不能仅根据左右布局分配。

### 7.6 第三位、多人组声、采样或合成声

能确认是稳定的第三位身份则增加 C 并留参照。不能确认人数和身份就记录未知声音的前／背景位置和备注。不是所有第三角色都该删除，不是所有“群声”都能给出真实人数。

人声采样、多人合唱、说话和合成歌声都要留类别和疑点；是否进入某个实验子集以后再决定，不先把原始信息丢掉。

### 7.7 念白、Rap、气口、哼唱、衬词

有节奏的 Rap 可按本项目演唱内容记录，并备注唱法；普通说话记“说话／念白”。持续哼唱、无词旋律和有身份的 adlib 仍是人声。短气口如果对身份不确定，不需要编造另一个人，可按边界策略记录并备注。

### 7.8 间奏、尾奏、前奏和没有歌词的声音

整首需要听到结尾，检查歌词之外的哼唱、喊声、和声和念白。在“歌词以外的人声”新增片段，不能因为 TTML 没有这一行就省略。

歌词全标完不代表全曲人声全标完。“已检查无歌词人声”必须是独立勾选项。没有听到也可以确认已检查，不能默认勾选。

### 7.9 制作信息、重复显示、零时长行

“作词／作曲／制作人”等不代表有人把这些字唱出来。确认后选择“制作信息／非独立歌词”，备注原因；不创建虚假人声片段。

源行时间为零或倒置的情况已经自动标出，保留原记录，不删行、不猜一个假时长。若是制作信息则按上项处理；若确实唱了，人工填写实际窗口和片段。

如果原歌词行本身有错词，不必顺便承担整首歌词校订。保留原文，备注与音频不符的位置，以免把文本错误误当身份或版本错误。

## 八、歌曲级检查表：完成之前逐项勾

### A. 文件与版本

- [ ] 固定本地音频，时长覆盖整曲，文件指纹已经记录。
- [ ] 不是试听、剪辑、Live 或另一重录版误配原版歌词。
- [ ] 前、中、后三个可复听定位点均已记录。
- [ ] 全曲偏移与局部漂移分开处理；最终时间都是音频时间。

### B. 身份

- [ ] 所有能确认的歌手都有稳定 ID。
- [ ] 每人有清晰参照，或写明参照缺失原因。
- [ ] 同人音区变化、假声、叠唱没有误分成另一个人。
- [ ] 第三人和未知群声没有因为超出 A/B 而被删除。
- [ ] 真实姓名、性别、左右位置没有被当作判断捷径。

### C. 时间与结构

- [ ] 每行看过实际窗口；短句和疑似重叠行重点核对。
- [ ] 句中换人与同时唱被区分。
- [ ] 前景／背景、已知／未知分别记录。
- [ ] 相邻片段不漏空档，不因为复制片段而留下旧确认。
- [ ] 前奏、间奏、尾奏和无词人声也检查过。
- [ ] 制作信息、重复行与源零时长问题都写明处理。

### D. 质量与保存

- [ ] 不确定的片段记录时间、原因，不照抄候选。
- [ ] 若身份能确认但边界不清，分别保留这两种判断。
- [ ] 整曲 A/B 编号一致，换段／副歌后没有翻转。
- [ ] 已导出文件，不只依赖 localStorage。
- [ ] 导入校验成功，并能重新载入已保存结果。
- [ ] 片段标注不被宣称为整曲完成；未听到的地方仍是未完成。

## 九、导出、导入和断点继续

### 9.1 每次暂停时

点“导出草稿备份”。它保留身份表、定位点、完成片段、未完成行、未知和备注。建议每完成一个连续段落就导出，至少每次离开页面前保存。草稿不是正式评测答案。

同浏览器可继续暂存；换浏览器或清理数据后，先选同一任务，再用“恢复导出文件”。旧录音版本的文件不允许直接覆盖新版本任务。恢复前先备份当前草稿。

### 9.2 导入人工结果

先选择本曲进度“部分核对”或“申请整首完成”，导出待校验文件。在 Mei 根目录执行：

```bash
python3 research/singer-diarization/tools/prepare_listening.py --import-annotation /实际路径/108576-detailed-partial.json
```

校验包括：歌曲 ID、音频与歌词指纹、录音版本确认、核对人、定位点、身份参照、时间范围、已听确认、不确定原因、行覆盖及整首状态。它验证记录的一致性与完整性，**不能自动证明你听对了谁**。

通过后保存到 `data/detailed_annotations/`。覆盖已有正式记录前会留下旧文件历史；生成任务不会抹掉已导入答案。导入后刷新任务台可恢复文件中的记录；若当前浏览器暂存较旧，优先恢复最新导出文件，而不是凭页面颜色判断哪份更新。

### 9.3 保留哪些文件

迁移独立项目时必须一起带走：音频、歌词快照、歌曲／候选清单、原标签、人工反馈日志、正式细标及其历史、导出的草稿。仅复制源码或 clone Git 不包含被忽略的 `data/`。

当前副本都在同一台机器，不构成异地备份。请把导出文件及数据目录另存到你自己的可靠备份位置；不要把商业歌曲音频和全文歌词直接推到公开仓库。整理代码、标注和音频的发布权限需要分别核对。

## 十、数据集何时算可用

至少区分四个状态：候选歌词、歌曲级合格、部分细标、整曲记录完成。已完成记录里仍要区分身份确定／未知、边界精确／近似，以及背景身份是否可判断。

后续报告应包括：

- 独立录音数与歌手多样性，不只报行数。
- 标准／困难／独唱负例／合成声／真人等子集。
- 已核对的歌词行数与时间覆盖，未听和未知的比例。
- 各身份独唱时长、同时唱的时长、背景人声覆盖。
- 短句和切换的分布，按可重算阈值统计。
- 标注误差、抽查修正和无法确认的边界。

严格的帧级 DER 不能只凭“每行是谁”推出来；需要足够细的活动边界、歌词以外人声和明确的评测范围。当前 v2 保留这些信息，但不是自动获得了高精度边界。先报告能够被标注质量支持的指标。

## 十一、减少返工的操作原则

1. 先用一首试运行整套保存、恢复、导入流程，再批量听。
2. 一次判断就记下“时间＋身份＋证据／疑点”，不只说“这首合格”。
3. 能确定的现在确定，不能确定的保留未知；以后只查疑点，不把未知混成正确答案。
4. 不因为后来更换短句阈值、合唱统计方式或训练模型而重听；详细片段允许重新计算这些标签。
5. 定期抽查少量已标片段，优先短句、合唱与身份变化处。若条件允许让另一位听者独立检查一部分；没有第二人时也要如实注明，不能声称多人一致性。
6. 疲劳时停下来保存草稿。继续工作从未完成位置开始，不为了凑数量降低判断质量。
